# Web UI をリバース プロキシで公開する

`dsh --profile web` は GUI をループバックのポートで配信するため、他マシンのブラウザは届かず、プロセスは自分の使うアドレスを知りません。前面のリバース プロキシが公開側（公開ホスト名、TLS、リスナーへ転送する前に剥ぐパス接頭辞）を担い、`--public-url` でブラウザの使うアドレスを DSH に伝えます

```sh
dsh --profile web --public-url https://app.example/ui/ --trusted-host app.example
```

## --public-url が担うのは告知だけ

| 項目 | 挙動 |
| --- | --- |
| 受け付け | `http://` または `https://` のルートにオプションのマウント接頭辞。正規化して `/` で終わる形にする |
| 供給先 | 印刷および起動 URL、`DSH_WEB_URL`、エージェントのランタイム コンテキストに示す Web GUI URL |
| 配信側 | Web サーバは origin ルートの配信を続け、マウントを学ばない。設定側の `publicUrl` フィールドも同じ告知を公表する |

## プロキシに求める動き

- **ブラウザ向けの `Host` を保つ**: フェンスは受信した `Host` を受け付けた権威と照合するので、リスナーのアドレスへ書き替えずに転送します
- **マウント接頭辞を剥ぐ**: リスナーは origin ルートの経路で応答するので、`/ui/api/...` の要求は `/api/...` として届く必要があります
- **アップグレードを転送する**: ページが開く全要求と WebSocket アップグレードを、`Upgrade`・`Connection` ヘッダを保ったままリスナーへ届かせます。HTTPS を配信するときは TLS がプロキシの外部側で終端します
- **Cookie の範囲を書き換える**: 平文 HTTP を配信するバックエンドは `Secure` のない host 専用 `Path=/` Cookie を出します。プロキシは `Path` をマウント（`/ui/`）へ書き換え、HTTPS 側で `Secure` を付けます。リスナー自身が TLS のときは `Secure` 済みなので、プロキシは `Path` の書き換えだけ行います
- **裸のマウントにリダイレクトする**: `/ui/` だけが入口で、起動トークンをセッション Cookie と交換するのはこれだけです。配信された文書は自分のディレクトリ基準で URL を解決するため、`/ui` の要求は `/ui/` として届く必要があり、剥いだ後ろ側ではその外部パスを再構成できません

## ブラウザの使う権威を信頼する

フェンスはループバック、リスナー自身のバインド アドレス、`--trusted-host` が挙げたすべての権威を受け付けます。それ以外の権威で届いたブラウザは、プロキシがどれほど正しくても全 API 呼び出しで 403 になるため、ブラウザに見える権威を `--trusted-host` に書いてください。`--public-url` の告知は表示用で、入場を許しません。ポート無しの指定は任意ポートに一致し、毎回別のポートを張るトンネルに合います。フェンスが担うのは要求の入場承認だけで、認証は印刷 URL の起動トークンと署名付きセッション Cookie が行います。TLS の終端位置はいずれでもこの仕組みを変えません。証明書はサーバからブラウザへの同一性保証で、その逆ではありません。

告知 URL もフェンスも待ち受けポートそのものは保護しません。ポートを信頼できるプロキシまたはネットワークに限定してください。

## 外側の脚を暗号化する

TLS はプロキシか、リスナー自身か、両方かで終端します。`--public-url` は告知に留まります。

| 構成 | 内容 |
| --- | --- |
| プロキシで終端 | ブラウザからプロキシの脚が保護される。プロキシからリスナーの暗号化はリスナーの TLS 設定次第 |
| リスナーで終端 | `--tls-cert` と `--tls-key` を渡す。どちらもプロセス作業ディレクトリ基準のパス。証明書ファイルはフル チェーン、鍵ファイルは非暗号化 PEM 秘密鍵 |

リスナー側 TLS の取り扱いには厳しい条件が付きます。

- DSH は証明書の取得、更新、監視を一切しません
- リスナーは各ファイルを1回だけ読みます。差し替えたらリスナーの再読込かプロセス再起動で反映します
- ペアの欠落または無効での起動は失敗し、HTTP へのフォールバックはしません
- 既定ポートは 3080 のままです。ネイティブ TLS はプロキシを要しませんが、プロキシ構成と `--public-url` は並行して対応が続きます
- TLS リスナーはセッション Cookie を `Secure` に付けます。ブラウザが Cookie を返し続けられるよう、公開のブラウザ向きの脚は HTTPS に保ってください

印刷 URL はプロセス credential を持つので、意図したユーザーにだけ共有します。

## 参考

- コマンドライン オプション `--public-url`・`--trusted-host`・`--tls-cert`/`--tls-key` は Web app リファレンスに文書化されています
- Web プロファイルでは `publicUrl` が `web-runtime` 行、`trustedHosts` が Connection 行、`tls` が webserver 行の設定に対応します
