# モバイル向けプロジェクト・タスク概要

プロジェクトdashboardの開始画面は **いまの状況** を示します。プロジェクト/タスクのcontext、現 evidence とその観察時刻、最新の結果、保留中の決定、停止可否です。メトリクス、タスク行、reply適用の詳細、進捗報告は折りたたまれます。下部ナビゲーションが概要・決定・詳細・停止案内を、プロジェクトを替えずに、回答を提出しないままの状態で手の届く範囲に置きます。

開始画面に載る情報の内訳は次のとおりです。

| 要素 | 内容 |
| --- | --- |
| プロジェクト/タスクのcontext | 今選んでいる範囲とその実行・報告の状態 |
| 現 evidence とその観察時刻 | いつ観察した何を根拠にしているか |
| 最新の結果 | input応答・reply・進捗報告のいずれか（区別付き） |
| 保留中の決定 | 回答待ち・取消・期限切れを除いた質問 |
| 停止可否 | この画面で止められるか、元のCLIへの案内か |

折りたたまれた表やメトリクスを開いても、宣言されたプロジェクトscopeは変わりません。回答の送信も行われず、閲覧だけで明確確認です。

## evidenceと欠落状態

タスクの `doing`/`done` は報告された値です。ネイティブ実行や受け入れを証明しません。reply先が未登録のタスクは実行状態が `実行状態は未取得` のまま、実行観察の欠落とプロジェクトの最終報告時刻を区別して表示します。

既存のreply consumerがある場合、consumerごとの最新の公開観察を要約します。接続確認、対象プロセスの終了、不明の区別です。これはreply先の一覧であり、プロセスの全数調査やタスク完了の証明ではありません。refresh失敗やSSE喪失後は、成功するまで表示中の状態は未確認になります。

最新の結果は相関済みinput応答、不確実/失効したreply、またはプロジェクト進捗報告になり得ます。ネイティブinput完了はACP resultとしてラベルし、進捗報告は宣言としてラベルして受け入れは別扱いです。保存済みreplyや通知配信はinput結果ではありません。未知の新しいinputが、より古いinputの成功を継承することはありません。

保留中の決定は回答済み・cancel済み・期限切れの質問を除外します。タスク選択時には、そのタスクに明示的に紐付いた質問だけが含まれます。未紐付けの質問は別途数えられ、プロジェクト全体の質問一覧から引き続き参照でき、選択タスクに黙って割り当てられることはありません。

## contextと詳細ナビゲーション

**確認する範囲** でタスクを選ぶか、タスク一覧からIDを開きます。選択は現在タブのsession storageにプロジェクトごと保存されます。ライブ更新や詳細の開閉でも選択は保持されます。スナップショットから消えたタスクは、明示的なmissing-taskラベル付きで選択中のIDを保持します。

ブラウザ認証後は `#task-＼id］` で再読込時にそのタスクが選択されます。credentialフラグメントだけがURLから除去されます。選択は表示contextであって、認証や制御権限ではありません。詳細な表・メトリクス・質問は宣言されたプロジェクトscopeを保ち、回答はその質問のrevision契約に従います。

質問の下書きは無関係な更新や詳細ナビゲーションで保持されます。revisionが変わったら、内容fingerprintが前の値に戻っていても、改めてreviewが要ります。前の選択/reviewは新しいrevisionを承認できません。

## 停止コントロール

プロジェクトモードには外部でattachしたACP adapter用のライブcontrollerがありません。そのため停止案内は「この画面からの停止は非対応」と述べて元のCLIを指します、記録されたPID/runメタデータからは停止権限を再構成しません。案内ナビゲーションも停止要求を出しません。

管理Harness入口は既存の[所有プロセススコープ](https://github.com/jimoto-no-llm/rustdsh/blob/main/docs/SCOPED-STOP.md)を使います。停止を選ぶと生きているrun/ownerとowned子孫への影響を先に表示します。cancel/Escは要求を出しません。確認でrun・owner・実行状態を再検査し、変わったまたは観察不能な対象はreview再要求になります。

既存の認証付きstop APIと段階的な所有権検査がそのまま強制手段です。「停止」と「子孫確認済み空」は区別されます。

## 検証境界

[記録済み検証](https://github.com/jimoto-no-llm/rustdsh/blob/main/docs/evidence/mobile-overview.md) には実際のブラウザキャプチャとネイティブfixture観察が含まれます。Responsive iframe幅はレイアウト確認であって、実電話やTailscaleの検証ではありません。

Issue #42の参加者シナリオは未実施です。事前説明なしに参加者へ「プロジェクト・状態/evidenceの時刻・最新結果・判断要否・停止場所」を問い、時間・誤り・不足情報を記録します。詳細の開閉やタスク選択の反復もrepeatし、停止cancelは独立に確認します。約30秒の目標は人間参加で試験されておらず、製品性能保証ではありません。

## 実務上の注意

- タスクの `doing`/`done` は報告値です。実行・受け入れを確かめるときは別のevidenceを参照します。
- プロジェクト画面の停止案内は誘導だけで実行しません。実際の停止は元のCLIか管理Harness入口から行います。

管理Harness入口での停止操作の流れです。

1. 停止を選ぶと、生きているrun/ownerとowned子孫への影響が先に表示されます。
2. cancel/Escは何の要求も出しません。
3. 確認を押すとrun・owner・実行状態を再検査し、変わったまたは観察不能な対象はreview再要求になります。
4. 実際の停止は既存の認証付きstop APIと段階的な所有権検査で強制されます。

「停止」と「子孫確認済み空」は別の状態として扱われ、表示上も区別されます。
