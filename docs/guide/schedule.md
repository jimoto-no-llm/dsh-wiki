# 予定実行

会話の中でモデルに頼むと、リマインダーの作成・一覧・表示・編集・一時停止・再開・削除ができます。各リマインダーは設定した繰り返しルールに従い、既存の会話、最初の配信で作る1つの新規会話、または毎回新しい会話へ指示を届けます。Webプロファイルにはホスト側のScheduleサービスと「自動化タスク」ページが付属します。

リマインダーを作る前に、モデルプロバイダを設定しておいてください。

## モデルに頼む

- standard・cordis・ptc プリセットは4つの予定ツールと、現在時刻やブラウザのタイムゾーンを渡すクロック文脈を宣言します。つまりこれらのプリセットでは schedule_create・schedule_list・schedule_view・schedule_edit が使えます。
- minimal プリセットはどちらも宣言しません。
- 委任されたサブエージェントにも4つのツールは見えますが、各ツールはサブエージェントからの呼び出しを拒否するため、読み書きはできません。

例として「毎日23:00（Asia/Shanghai）に天気を確認して」と頼むと、返答の下にカードが表示され、名前と頻度を確認できます。頻度が「毎日23:00」になっているか（一度きりになっていないか）を必ずチェックしてください。一度きりのリマインダーは配信後も繰り返しにはなりません。

モデルに頼らず作るには、サイドバーの「自動化タスク」から「手動で作成」を選びます。ダイアログでは名前・指示・実行先（Run in）・リンクされたワークスペース・実行時刻を入力します。「既存会話を作成して使い回す」は最初の実行で会話を1つ作り続けて使い、「毎回新しい会話」は実行ごとに別々の会話を作ります。

配信で作られた会話は作業ディレクトリに登録済みのワークスペースに所属し、リマインダー名がタイトルになります。毎回新規会話のタスクでは、起動時刻もタイトルに入ります（例: Weekday digest · 2026-10-12 09:00）。

## タスクの確認・実行・削除

- 「自動化タスク」ページではセッションを開かずに全リマインダーを閲覧できます。タスク名・指示・会話idで検索し、状態（有効/一時停止/終了）で絞り込み可能です。
- 行は実行予定時刻の早い順に並び、有効タスクには次回予定のローカル時刻が表示されます。
- タスクを選ぶと詳細が開き、次回実行・指示・繰り返し・実行先を確認できます。「Records」で最新20件の配信記録を読み込み、「Load more」で次ページを追加します。
- 「Run now」は待機中の配信をすぐに実行します。会話がアーカイブ済みでもタスクの詳細と削除は可能です。
- 「Delete task」で今後の配信を止めて一覧から外します。削除は保存済みの配信記録も一緒に消すので、履歴は残りません。

## タスク編集

編集は名前・指示・繰り返しルール・配信先を対象に、一時停止中や終了済みのタスクでも行えます。保存までドラフトとして保持され、「Save changes」は変更したフィールドだけを1回の更新で送ります。既存会話への配信タスクで実行先を変えると、以後の実行は新規会話を作るようになります。繰り返しは、1回だけ・N分/N時間ごと・毎日・週次/月〜金・毎月・カスタムから選べます。タイムゾーンは最近使ったゾーンを先頭に表示し、UTCオフセット・IANA ID・都市名で検索できます。

保存が競合した場合（配信などで他から変更された場合）はホストが保存を拒否し、何も変わりません。「Load latest version」でドラフトを最新版に置き換えるまで保存は無効になります。

## 配信の挙動

- ホスト稼働中は、リマインダーの予定時刻になると対象セッションを復元または作成し、作業を中断せずフォローアップを順番待ちに入れます。
- 再起動時は保存済みタスクを確認し、期限切れの1回きりタスク、または各繰り返しタスクの最新の取りこぼし1回だけを配信します。ホストを閉じるとスケジューリングは止まります。
- 繰り返しルールはIANAゾーンの現地時刻に従い、存在しない現地時刻はスキップ、繰り返しのある現地時刻は早い方の瞬間を使います。
- 配信の「ちょうど1回」は保証されません。インボックス保存後のクラッシュなどで、保存記録がないまま配信が繰り返されることがあります。
- ホスト終了時にインボックスへ残っていたメッセージは破棄されます。保存記録は残りますが、モデルはそのメッセージを受け取りません。
- 保存記録は deliveryHistoryDays（受領時刻から遡る日数）と deliveryHistoryRecords（最大件数）で整理され、最新の受領記録は必ず残ります。
