# 選択的履歴バックアップ

`dashboard/cli.mjs backup` は、タスク・質問・回答・決定・エビデンスの**歴史的記録**を移植可能なアーカイブに書き出します（issue #46）。プロジェクトディレクトリやダッシュボード状態ディレクトリのコピーはしません。リストアは タスク → 決定リビジョン → 質問 → 回答 の関係と受け入れエビデンスIDを、読み取り専用の `history_backups` コレクションとして保持します。`backup history` と既存の認証付き状態リソースで閲覧できます。現在のタスクボード、待機インボックス、フィードバック消費者、元エージェントセッションをアーカイブから再現することはありません。

## 選択する

ソースプロジェクトのローカルダッシュボードを起動し、選択ファイルを書きます。

```json
{
  "types": ["tasks", "answers", "decisions", "evidence"],
  "task_ids": ["task-1"]
}
```

`types` は明示必須です。任意の `task_ids`、`question_ids`、`evidence_ids` がそれぞれの実体を絞り、省略/nullは全件、`[]` は0件です。回答/決定にはタスクと質問の両方フィルタが効きます。旧形式の質問はタスク結合を持たないため、質問IDのみで選びます。回答やエビデンス参照が必要とする依存は、型が選択されていなくても含まれます。選択した歴史回答は現在のリビジョンではなく実際の質問リビジョンを保持します。

含める `since`/`until` は正準UTCタイムスタンプで、タスク更新・回答作成・決定更新時刻を絞ります。依存は範囲外にあっても含まれます。エビデンス索引参照にタイムスタンプはないため、日付範囲でのエビデンス選択は拒否され、タスク/エビデンスIDで選びます。

```sh
node dashboard/cli.mjs backup preview --project /path/to/source --selection-file selection.json
```

previewは件数、選択レコード、ソースリビジョン、選択ダイジェスト、保持されるテキストフィールド全パスを返します。**全ソース自由文は既定で差し押さえられます**。タイトル、質問、回答、選択肢ラベル、diff、条件は `null` になります。どの表現が公開安全かを正規表現で推測しません。コード・ログ・画像・コマンド引数・ファイルパス・トークン・クレデンシャル・ネイティブセッション/ラン結合・実行時URL・消費者許可・イベント購読秘密はコピーされません。エビデンスは `rdsh-evidence:＼source-project-id］/＼evidence-id］` のポータブル参照に `freshness: "unverified"` を付します。

有用な文章を残したい場合は、独立にレビューして**置換テキスト**を特定パスへ供給します。

```json
{
  "source": { "project_id": "0123456789abcdef", "revision": 12, "acceptance_revision": 3 },
  "selection_digest": "COPY_THE_PREVIEW_SELECTION_DIGEST",
  "replacements": [
    { "path": "tasks/task-1/title", "value": "Reviewed task title" },
    { "path": "answers/answer_1/answer", "value": "Proceed with that change" }
  ]
}
```

ソースリビジョンか選択の変更がレビューを無効化します。未知パス、重複パス、既知クレデンシャル接頭辞/代入、bearer/basicヘッダ、JWT/秘密鍵、64-hex文字列、コードフェンス/共通コード宣言、userinfo・query・fragment付きURLは拒否されます。これは一般的ミスへのガードであり万能の秘匿検出ではありません。レビューした文章に置かれた未知の秘密をこの機能が特定することには限界があり、レビューファイル自体も非公開に保ってください。

```sh
node dashboard/cli.mjs backup export --project /path/to/source --selection-file selection.json --review-file review.json --output-file history.json
node dashboard/cli.mjs backup inspect --archive-file history.json
```

`--review-file` を省くと構造履歴のみ（文章保持）で書き出します。共有前に `inspect` で書き出し文と保持マニフェストを確認します。出力は**新ファイル**で、既存ファイルは上書きしません。対応環境では mode `0600` で作成します。Windowsは含むディレクトリのACLが効くため、非公開ディレクトリを選んでください。自動アップロード・出版は行われません。

## ターゲット側の認証でリストアする

空のターゲットプロジェクトにダッシュボードを起動します。新しいランタイムがソースと独立に新しい管理者・MCP・ブラウザ鍵を発行します。ターゲットの現在リビジョンを取得し、アーカイブを検査してからリストアします。preview/export/history/restoreは対象プロジェクトの**ローカル管理者**クレデンシャルと直接ループバックを要求し、`Forwarded` や `X-Forwarded-For` 付きの要求は拒否されるため、Tailscale ServeやHTTPリバースプロキシ経由は使えません。バックアップコマンドはダッシュボードホストで実行します。MCP・ブラウザ・予算生成・返信消費者の各鍵は、アーカイブを輸入したりバックアップ権限を自分へ与えたりできません。オフライン検査にランタイムは不要です。

状態書き込みの前に、スキーマ・境界・フィールド許可リスト・正準SHA-256・レビュー済み/保持パス・全実体参照・現在リビジョン・ID競合を検査します。実存のタスク/質問IDや過去の復元IDとの衝突は拒否です。上書き、ID再割当、自動マージはありません。承認決定は常に歴史のまま `execution_authorized: false` です。輸入されたコマンド、待機返信、ネイティブ再開許可、予算ポリシー、イベント配信カーソル、callbackはありません。輸入エビデンスで現在タスクの受け入れ検証が通ることはなく、ソースエビデンスとターゲット入力は別途再読・再検が必要です。

履歴は輸入/開封時に全量検証してメモリで再帰的に凍結します。通常の状態更新はその不変履歴を保持し、キャッシュされたIDで競合を確認するため、書き込みごとの文章/チェックサム再走査を避けます。コレクションの差し替えは状態書き込み前に再度全量検証します。

## フォーマットと制限

アーカイブはUTF-8 JSONで `format: "rdsh-history"`、`schema: 1` にUUID、作成時刻、ソースリビジョン、正準化選択、歴史専用ポリシー、5つのレコード配列、内容レビューマニフェスト、正準SHA-256を持ちます。ZIPでもファイルシステム展開でもなく、参照がファイルを書くことはできません。チェックサムは偶然の破損検出であり、再計算する悪意ある作成者に対する真正性証明ではありません。出身が重要ならアーカイブは信頼置きに保管してください。

最大ファイル2 MiB、各実体配列2,000件、保持履歴は100アーカイブ/8 MiBです。超過入力は古い履歴を落とさず失敗します。エンティティIDは1〜128文字のASCII英数字/ドット/下線/ハイフンで英数字開始が必須です。互換の無い旧IDは黙って再割当せず書き出しを止めます。中断された書き出しは排他作成の部分ファイルを残すことがあり、検査/リストアはこれを拒否します。未対応スキーマの移行や実行状態の全復元はしません。

## 実務上の注意

- 最初に `preview` → `inspect` で共有内容を必ず目で確認する。秘匿検出は「ある種のありがち情報」だけを止めるガードです。
- リストア先は必ず空プロジェクト。上書きやマージは設計上ないので、忘れるとID衝突で確実に止まります。
