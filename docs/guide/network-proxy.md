# ネットワークとプロキシ

Dshは外向きの要求（モデル呼び出し、Web検索、ページ取得、HTTP経由のMCPサーバ）を、標準のプロキシ環境変数で指定されたプロキシに経路付けます。変数は起動時に読まれ、他の設定は不要です。一部の経路は設計上、または実行時の制限で直結のまま残ります（「直結のままのもの」を参照）。

## 変数を書き出す

```sh
export HTTPS_PROXY=http://127.0.0.1:7890
export HTTP_PROXY=http://127.0.0.1:7890
```

シェルプロファイルへ入れてすべての `dsh` 呼び出しに継承させるか、APIキーの隣の `$DSH_HOME/.env`（既定は ~/.dsh/.env）へ置きます。書き出し済みの変数はそのファイルより常に優先です。プロジェクト自身の .env は設定できません。git clone とともに届くファイルが通信先を決めることがないよう、Dshは起動を拒否します。認証付きプロキシは `http://user:password@proxy.example:8080` の形で渡します。DshはそのURLを決して表示に戻さず、拒否された変数の名前だけを診断に出します。

## ブラウザはプロキシを使うのに端末は使わない件

「システムのプロキシ」という全ソフト共通の仕組みは存在せず、独立した3経路があります。

| 仕組み | 従うもの |
|---|---|
| OSのプロキシ設定 | Safari、macOSのネイティブアプリの多く、ChromeとEdge |
| HTTP_PROXY / HTTPS_PROXY 環境変数 | curl、git、npm、pip、そしてDsh |
| TUNモード（仮想NIC） | 透過的にすべて |

Clashのようなプロキシアプリの「システムプロキシ」スイッチは1つ目だけを書き込みます。ブラウザは拾いますが、コマンドラインツールには見えません。だからこそ変数の書き出しが別の手順ですし、TUNモードを付けると変数なしで両方が通る理由でもあります。DshはOSのプロキシ設定を読みません。変数を書き出すか、TUNモードを使ってください。

## 直結へ抜く選択（NO_PROXY）

`NO_PROXY` は直結させるホストを列挙します。たとえば `export NO_PROXY=internal.example.com,.corp.example.com,registry.local`。エントリはホストとそのすべてのサブドメインに一致し、先頭の `.` や `*.` も同じ意味で受け付けます。`:port` を付けられ、`*` はすべてをバイパスします。

- ポイント1: CIDR範囲は効きません。OSのバイパスリストにありがちな `10.0.0.0/8` を書き写しても効果がなく、ホスト名かドメイン接尾子を使います。
- ポイント2: `localhost` や `127.0.0.1` は書かなくてよいです。Dshはループバックを常にバイパスします。自身のWeb UIとローカルサーバがプロキシ経由で環流するのを避けるためです。

## 知っておきたい制限

- **SOCKSプロキシは非対応**です。socks5:// の値は起動時に報告してスキップされ、Dshはそのスキームを直でつなぎます。HTTPS_PROXY にsocks5を入れてもHTTP_PROXYが使えるままなら https: は直結のままで、HTTPプロキシを借りません。プロキシアプリのHTTPポートを指してください（多くは両方を公開し、HTTP側は隣のポート番号が普通です）。
- **ALL_PROXY だけで両スキームにフォールバックします**（Nodeとcurlでは扱いが違う点）。とはいえ明示の HTTPS_PROXY のほうが分かりやすいです。
- **TLSを検査する社内プロキシには証明書が要ります。** プロキシに届くのに証明書エラーが出るなら、起動前に `export NODE_EXTRA_CA_CERTS=/path/to/corporate-ca.pem` を。Nodeはこの変数をプロセス開始時にしか読みません。
- **Dshが走らせるツール群は同じプロキシに従います。** bashツールのコマンド、git、gh、子プロセスのMCPサーバは変数を継承します。子のNodeプログラムは自分のインストール済みランタイムを使い、Node 22.21+ と Node 24+ は変数に従い、それより古いランタイムは直結です。Dshが拒否する値（SOCKS URLなど）が入っていてもNode系ツールは起動失敗でなく直結に回りますが、curlとgitはその値を読みます。
- **プロキシURLのパスワードはそのツール群にも届きます。** 普通の環境変数なので、モデルが書いたコマンドを含むすべてのコマンドが読め、環境を表示するコマンドはパスワードを保存される出力へ載せます。気になるなら認証情報なしの入口をプロキシに作るか、URL以外の認証方法にしてください。

## 直結のままのもの

- このマシン上の対象はすべて直結です。ループバックは常にバイパスされます。
- モデルが書いたコード。workflowのワーカーとNode ptcランタイムはプロキシ設定を受け取らないため、パスワード入りの可能性があるURLを読めません。直結要求側で必要なプロキシは各自設定し、実行サンドボックスには従います。
- 使用量テレメトリ。OTLP exporterはNode独自のHTTPクライアントを使うため常に直結で、出口が塞がれていれば単純に失敗します。`DSH_TELEMETRY_MODE=DISABLED` で全体を停止できます。
- リテラルなプライベートアドレスへの web_fetch（`http://10.0.0.5/` など）はプロキシへ渡されず拒否されます。プロキシなしの場合と同じ拒否です。

## 動作確認

エージェントにページ取得を頼み、プロキシアプリの接続ログを見ます: `dsh --profile headless "fetch https://example.com and tell me the page title"`。ログに出ない場合は `env | grep -i proxy` で、変数がDshの環境まで生きているか確認します。
